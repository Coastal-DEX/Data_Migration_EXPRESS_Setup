## 1. Before you deploy

This client deploys from its own branch, `deploy/TOY`, with the button in section 2. You do not need the Salesforce CLI. The Deploy button on the repo's front page deploys a different client and does not reach this one.

These org settings are prerequisites. They are org settings, not metadata, so this repo cannot deploy them. Do them in this order: each one can depend on the one before it.

1. Turn on Toy Feature Pack (Setup > Toy Settings). **Irreversible:** it cannot be turned off once enabled.
2. Create the `Account` record types `Branch`, `Org_Unit`, active and available to the seeding user's profile.
3. Enable State and Country/Territory Picklists (Setup > State and Country/Territory Picklists).
4. Turn on Set Audit Fields upon Record Creation (Setup > User Interface). Audit columns: `Case.CreatedDate`

## 3. Check, census, seed, census

Run each script as Anonymous Apex in Web Console. Developer Console is off by default in new orgs. Open Setup, then the gear menu > Web Console. Press Cmd+Shift+P (Ctrl+Shift+P on Windows), choose SFDX: Create Anonymous Apex Script, paste the script from this folder's `scripts/` on GitHub, right-click, and choose SFDX: Execute Anonymous Apex. The result arrives as the debug log. An admin can turn Developer Console back on at Setup > Development > Web Console > Enable Developer Console.

1. Run `scripts/check-setup.apex` as Anonymous Apex. It prints `SETUP OK`, or throws `SETUP INCOMPLETE` / `ALREADY SEEDED` naming the first gap. Fix that gap and run it again.
2. Run `scripts/census.apex` with `MODE = 'BEFORE'`. Copy the line it prints.
3. Run `scripts/run-seed.apex`. It runs 5 Batch jobs, one per step, chained.
4. Wait for the email, or query `Seed_Step_Result__c`. The run passes only on `SEED PASS`. A Completed job is not proof of success.
5. Run `scripts/census.apex` with `MODE = 'AFTER'` and the BEFORE line pasted in. Every row must say PASS.

Every seeded record is owned by the user who ran the seed. The original owner username is kept in the owner lineage field on each object.

## 6. Enforcement layer

Active for learner loads. The seed turns it off while it loads and back on when it ends (`Migration_Settings__c.Bypass_Automation__c`).

| Id | Kind | Object | Component | Expected error |
| :-- | :-- | :-- | :-- | :-- |
| T1 | VALIDATION_RULE | `Case` | `Toy_Closed_Needs_Reason` | Closed needs a reason |
| T2 | TRIGGER_REQUIRED | `Asset` | `ToyAssetNeedsInstallDate` | Installed assets need an install date |

Not in this release: T3 (DUPLICATE_RULE).

If a run stops before its last step (Setup > Apex Jobs shows a failed or aborted ExpressSeedBatch and no verdict arrives), run `scripts/reset-bypass.apex` so the enforcement layer is active again.

## 7. Reset

Run `scripts/reset-data.apex` with `MODE = 'REPORT'` first. Set `MODE = 'DELETE'` and rerun until every count is 0. Then verify with `scripts/census.apex`.
