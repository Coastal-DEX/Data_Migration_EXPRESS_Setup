## 1. Before you deploy

Work in this folder only. Every command below runs from `clients/FINS`:

```
cd clients/FINS
```

The repo root holds a different client. A deploy from the root does not reach this one.

These org settings are prerequisites. They are org settings, not metadata, so this repo cannot deploy them:

1. Person Accounts enabled (record types `Account.PersonAccount`)
2. State and Country/Territory Picklists enabled
3. Contacts to Multiple Accounts enabled
4. Set Audit Fields upon Record Creation enabled (Setup > User Interface). Audit columns: `Case.ClosedDate`, `Case.CreatedDate`, `Task.CreatedDate`
5. `Account` record types active and available: `Business_Account`, `PersonAccount`

## 2. Deploy and assign

```
sf project deploy start --test-level RunLocalTests
sf org assign permset --name EXPRESS_Seed_Admin
```

## 3. Check, census, seed, census

1. Run `scripts/check-setup.apex` as Anonymous Apex. It prints `SETUP OK`, or throws `SETUP INCOMPLETE` / `ALREADY SEEDED` naming the first gap. Fix that gap and run it again.
2. Run `scripts/census.apex` with `MODE = 'BEFORE'`. Copy the line it prints.
3. Run `scripts/run-seed.apex`. It runs 13 Batch jobs, one per step, chained.
4. Wait for the email, or query `Seed_Step_Result__c`. The run passes only on `SEED PASS`. A Completed job is not proof of success.
5. Run `scripts/census.apex` with `MODE = 'AFTER'` and the BEFORE line pasted in. Every row must say PASS.

Every seeded record is owned by the user who ran the seed. The original owner username is kept in the owner lineage field on each object.

## 6. Enforcement layer

Active for learner loads. The seed turns it off while it loads and back on when it ends (`Migration_Settings__c.Bypass_Automation__c`).

| Id | Kind | Object | Component | Expected error |
| :-- | :-- | :-- | :-- | :-- |
| A01 | TRIGGER_CPU | `Account` | `ExpressAccountCpuBurn` | System.LimitException: Apex CPU time limit exceeded (at batch size 200) |
| A04a | VALIDATION_RULE | `FinancialAccount` | `VR_Closing_After_Opening` | Closing Date cannot be before Opening Date. |
| A04b | VALIDATION_RULE | `FinancialAccount` | `VR_Closed_Requires_ClosingDate` | A Closed financial account requires a Closing Date. |
| A04c | VALIDATION_RULE | `FinancialAccount` | `VR_Loan_Requires_InterestRate` | A Loan requires an Interest Rate. |
| A05 | TRIGGER_REQUIRED | `Account` | `ExpressAccountRequireTaxId` | Tax ID is required for Corporate segment |
| A07 | FLOW_CUSTOM_ERROR | `Case` | `Express_Case_Closed_Requires_Reason` | Closed cases require a Reason |
| A08 | FLOW_CUSTOM_ERROR | `Opportunity` | `Express_Opp_ClosedWon_Requires_Amount` | Closed Won requires Amount |

Not in this release: A02 (FLOW_FIELD_REWRITE), A03 (TRIGGER_ROLLUP_LOCK), A06 (DUPLICATE_RULE).

If a run stops before its last step (Setup > Apex Jobs shows a failed or aborted ExpressSeedBatch and no verdict arrives), run `scripts/reset-bypass.apex` so the enforcement layer is active again.

## 7. Reset

Run `scripts/reset-data.apex` with `MODE = 'REPORT'` first. Set `MODE = 'DELETE'` and rerun until every count is 0. Then verify with `scripts/census.apex`.
